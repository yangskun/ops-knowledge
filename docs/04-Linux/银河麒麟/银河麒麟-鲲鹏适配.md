# 银河麒麟 + 鲲鹏(ARM)适配要点

## 结论先行

国产化适配的核心是**架构匹配**:鲲鹏是 ARM64(aarch64),银河麒麟默认只认 ARM 版软件包。适配三板斧:**确认环境 → 换用 ARM 版软件源/软件包 → 编译类软件用 ARM 原生或交叉编译**。x86 的 deb/rpm 直接装必报错;容器镜像要 ARM64 版;JDK/数据库/中间件优先选鲲鹏认证版本。

## 现象

- 软件安装报错 `Wrong architecture 'amd64'` 或安装后无法运行(段错误/Segmentation fault)
- 从 x86 迁移的软件在麒麟+鲲鹏上起不来、报找不到依赖
- Docker 拉取通用镜像后容器启动失败或性能极差

## 原因推测(分层定位)

| 层 | 常见原因 |
|---|---|
| 架构 | x86(amd64)二进制装在 aarch64 系统上 |
| 软件源 | 源配置指向 x86 仓库,拉包报 404/架构不符 |
| 依赖 | ARM 版主程序缺少 ARM 版依赖库 |
| 容器 | 镜像为 amd64 架构,Docker 无 qemu 无法直接运行 |
| 运行时 | JDK 为 x86 版,Java 应用启动崩溃 |

## 分步操作

### 第 1 步:确认环境(先看清底子,1 分钟)

```bash
# 架构(重点:aarch64=鲲鹏/ARM,x86_64=Intel/AMD)
uname -m

# 系统版本(银河麒麟特有命令,显示系统+内核版本)
nkvers

# 标准方式
cat /etc/os-release
uname -r          # 内核版本(鲲鹏 920 通常配套 4.19+ 内核)

# CPU 信息
lscpu | grep -E "Architecture|Model name"
```

### 第 2 步:检查软件包架构(装前必查)

```bash
# 查看已装软件架构
dpkg --print-architecture          # 期望输出 arm64(或 amd64)
dpkg -l | grep <软件名>

# 查看待安装包/二进制架构
file /path/to/xxx.deb              # 看 package 架构字段
file /usr/bin/xxx                  # ELF 64-bit LSB ... ARM aarch64 = 正确
ldd /usr/bin/xxx                   # 依赖库是否缺失(ARM 版必须 ARM 依赖)
```

### 第 3 步:配置正确的软件源(ARM 版)

```bash
# 备份原源
cp /etc/apt/sources.list /etc/apt/sources.list.bak

# 麒麟官方源(ARM 版,以官网/内网镜像为准)
# 关键点:架构字段要用 arm64,且镜像本身是 ARM 仓库
cat /etc/apt/sources.list
# 例:deb [arch=arm64] https://mirrors.kylinos.cn/kylin/KYLIN-V10-SP1 arm64 main

apt update
apt install -y <软件名>
```

> ⚠️ 若公司有内网麒麟源,优先用内网(外网源可能被墙/版本滞后)。改源后 `apt update` 报 404 多为架构或路径问题。

### 第 4 步:运行时适配(JDK/数据库/中间件)

| 组件 | 适配要点 |
|---|---|
| **JDK** | 装 ARM 版:华为**毕昇 JDK**(鲲鹏官方推荐)或 OpenJDK arm64;`java -version` 前先 `file $(which java)` 确认架构 |
| **数据库** | 达梦/人大金仓/openGauss 均有**鲲鹏认证版本**,去厂商官网下 aarch64 安装包,别用 x86 包 |
| **中间件** | 东方通/金蝶天燕有 ARM 版;Tomcat 是纯 Java 无架构限制(只要 JDK 对) |
| **代理/缓存** | Nginx/Redis 等编译类:ARM 源里有 aarch64 包,直接 apt/yum 装 |

```bash
# 查看当前 Java 是否 ARM 版
file $(readlink -f $(which java))   # 应显示 ARM aarch64
```

### 第 5 步:源码编译(无现成包时)

```bash
# 直接在鲲鹏机器上原生编译(推荐,保证最优指令集)
./configure && make -j$(nproc) && make install

# 或 x86 机器交叉编译(aarch64 目标)
# 安装交叉工具链
apt install gcc-aarch64-linux-gnu
./configure --host=aarch64-linux-gnu && make
```

> 纯 x86 二进制又无源码:可用 `qemu-aarch64` 用户态模拟跑(性能损失 30~50%),仅作应急。

### 第 6 步:容器适配(Docker/镜像)

```bash
# 查看镜像架构(amd64 镜像在 ARM 主机上默认跑不起来)
docker inspect <镜像名> | grep -i architecture
# 或
docker manifest inspect <镜像名>

# 方案一:直接拉 arm64 镜像(镜像名带 -arm64 / 多架构镜像自动匹配)
docker pull <镜像名>:latest        # 多架构镜像(manifest list)会自动拉 arm64

# 方案二:用 buildx 构建 ARM 镜像
docker buildx build --platform linux/arm64 -t <镜像名> .

# 方案三:qemu 模拟运行 x86 容器(性能损耗大,仅测试)
docker run --platform linux/amd64 <镜像名>
```

> 鲲鹏环境建议从**华为云 SWR 镜像仓库**或厂商 ARM 镜像拉取,性能最好。

## 验证方法

```bash
# 1. 架构全部一致:aarch64
uname -m && file /usr/bin/<软件> | grep -o "ARM aarch64"

# 2. 依赖完整(ldd 无 not found)
ldd /usr/bin/<软件> | grep "not found" | wc -l    # 应为 0

# 3. Java 应用:正常启动,无 SIGSEGV
java -version

# 4. 容器:docker run 正常,进程存活
docker ps | grep <容器名>

# 5. 业务冒烟:功能/性能达到预期(有基准的先跑基准对比)
```

## 注意事项 / 踩坑记录

- **x86 包硬装 = 系统级隐患**:`dpkg -i` 强装 amd64 包可能破坏包管理器,报 `Wrong architecture` 就停手,别加 `--force-architecture`
- **源配置三查**:架构字段(arm64)、镜像本身架构、版本号(KYLIN-V10-SP1/SP2 路径不同)
- **JDK 是最大坑**:很多应用"装好了跑不起来"其实是 x86 JDK;毕昇 JDK + 鲲鹏是官方组合
- **国产数据库/中间件认准"鲲鹏认证"版本**,通用版( x86)装不上或性能差
- **Docker 别默认 pull**:先 `docker manifest inspect` 看架构;`--platform linux/amd64` 跑 x86 镜像仅在开发测试可用
- **交叉编译注意依赖**:静态链接优先,动态链接需目标机安装对应 ARM 依赖库
- 银河麒麟 V10 分**桌面版(apt)与服务器版(apt 或 yum 视 SP 版本)**,包管理命令先 `cat /etc/os-release` 确认
- 生产环境:装包前备份(配置/数据),变更窗口操作;回滚预案 = 原源备份 + 原软件版本留档
